Windows prepara código con IA local: MAI Code 1.1 Flash y rutas híbridas con HydraFusion

Microsoft anuncia una versión local cuantizada de MAI Code 1.1 Flash y enrutamiento híbrido de GitHub HydraFusion para usar modelos en el PC o en la nube. La integración con Copilot y VS Code llegará como preview experimental más adelante en octubre.

Abrir versión interactiva

Resumen ejecutivo

Microsoft anunció el 7 de octubre una versión cuantizada local de MAI Code 1.1 Flash y planes para incorporar modelos del PC al enrutamiento de GitHub HydraFusion. La preview de integración está prevista para más adelante en octubre; las funciones de Copilot híbrido llegarían en los próximos meses. No es una disponibilidad general inmediata de todas las capacidades.

Microsoft presentó el 7 de octubre de 2026 una ampliación de su estrategia de inteligencia híbrida en Windows: ejecutar parte del trabajo de IA en el propio ordenador y enviar otras tareas a la nube. Entre los anuncios diferenciados figuran una versión local de MAI Code 1.1 Flash y una extensión de GitHub HydraFusion que podrá elegir modelos locales para tareas de programación. Esta noticia se refiere al software de modelos y enrutamiento; es distinta de Microsoft Execution Containers, que se ocupa de los permisos, y de los equipos RTX Spark, que proporcionan el hardware.

En 30 segundos

  • MAI Code 1.1 Flash tiene 137.000 millones de parámetros totales y 6.800 millones activos, según Microsoft.
  • Microsoft anuncia cuantización a 3 bits y contexto local de 256K; no publica una comparación independiente de calidad.
  • HydraFusion local llegará a GitHub Copilot, Copilot CLI y VS Code en preview experimental más adelante en octubre.

Qué se anunció y qué no

El punto central no es que todo Copilot funcione ya sin internet. Microsoft describe un sistema que selecciona dónde procesar cada tarea, considerando coste, privacidad, recursos del equipo y complejidad. En esa arquitectura, una solicitud simple podría resolverse con un modelo local mientras otra más exigente necesitaría la nube. La compañía habla de disponibilidad futura de varias funciones, por lo que debe distinguirse el anuncio técnico del acceso real para todos los usuarios.

En su comunicación de Windows, Microsoft separa las capacidades de ejecución de modelos, la orquestación y la contención de agentes. MAI Code 1.1 Flash aporta una opción de modelo especializado en programación. HydraFusion representa el mecanismo de selección. MXC limita lo que un agente puede hacer al ejecutar herramientas. Confundir las tres piezas llevaría a creer que un modelo cuantizado, por sí solo, garantiza seguridad o que instalar un PC nuevo activa automáticamente todas las experiencias prometidas.

Detalles de MAI Code 1.1 Flash

Microsoft afirma que MAI Code 1.1 Flash dispone de 137.000 millones de parámetros totales y 6.800 millones activos. La diferencia sugiere una arquitectura en la que no todos los parámetros intervienen en cada paso de inferencia. La empresa anuncia una variante a precisión de 3 bits que reduce el tamaño del modelo casi un 80% respecto de su representación de referencia y mantiene una ventana de contexto de 256.000 tokens en la configuración local descrita.

La cuantización reduce requisitos de memoria y puede permitir ejecutar modelos más grandes en hardware personal, pero no elimina todos los costes. También se necesitan memoria para contexto, ejecución de herramientas y procesos del sistema. Microsoft afirma preservar calidad de programación con la optimización; esa afirmación no equivale a una batería de pruebas independientes ni garantiza idénticos resultados en cualquier equipo. No se publicó un precio separado de la variante local ni una licencia abierta universal para los pesos.

Otros modelos y el runtime de Windows

Microsoft menciona planes para ejecutar en RTX Spark una variante futura de Nemotron de NVIDIA, con más de 70.000 millones de parámetros y cuantización de 2 bits que utilizaría algo más de 20 GB de memoria, así como DeepSeek V4 Flash de 284.000 millones de parámetros. Es importante no presentar esas cifras como configuraciones listas para descargar por cualquier usuario hoy: algunas se describen expresamente como próximas y dependen de optimizaciones y hardware.

Windows ML también incorpora soporte anunciado para llama.cpp, un componente utilizado ampliamente para ejecutar modelos abiertos de forma local. Microsoft plantea que Windows ML pueda aprovechar GPU, NPU y CPU. Esto amplía opciones de experimentación para desarrolladores, pero no implica que todos los modelos tengan aceleración equivalente ni que sus licencias permitan los mismos usos. La compatibilidad práctica dependerá del formato del modelo, del backend, de los controladores y de la memoria disponible.

HydraFusion: elegir modelo según la tarea

GitHub HydraFusion ya se utilizaba para enrutar tareas entre modelos en la nube. Microsoft anuncia su extensión a Windows para incluir modelos ejecutados en el dispositivo. La preview experimental está prevista más adelante en octubre de 2026 para GitHub Copilot, GitHub Copilot CLI y Visual Studio Code. La expresión preview es clave: no equivale a disponibilidad general, ni demuestra que todas las solicitudes de esos productos se ejecutarán localmente.

El valor potencial es operacional. Un desarrollador podría reservar la nube para problemas complejos y usar modelos locales cuando convenga reducir latencia, tráfico de datos o consumo de tokens facturados. Pero el ahorro real depende de la carga de trabajo y del coste del hardware. Ejecutar un modelo local consume electricidad, memoria y tiempo de mantenimiento. Además, enviar una tarea al equipo no asegura privacidad si las herramientas del agente siguen accediendo a servicios externos.

Copilot híbrido y límites de disponibilidad

Microsoft también anticipa que Copilot en equipos Copilot+ podrá utilizar contexto local, realizar acciones con permiso del usuario y combinar modelos locales con modelos remotos. Estas experiencias se desplegarían durante los próximos meses, no necesariamente el día del anuncio. La empresa menciona asimismo un gateway nativo de Windows para facilitar la configuración de OpenClaw en miniordenadores, acompañado de integración con MXC. Son piezas del ecosistema, no evidencia de que todas las instalaciones actuales las tengan activadas.

Para empresas, el anuncio abre la posibilidad de políticas que determinen qué tareas deben permanecer en el dispositivo y cuáles pueden ir a servicios remotos. Sin embargo, el texto público no define un precio universal ni requisitos mínimos homogéneos para todo el conjunto. Cada aplicación y modelo necesitará su propia comprobación de disponibilidad, consumo y seguridad antes de tomar decisiones de despliegue.

Análisis Gazette y recomendaciones

La competencia se desplaza desde quién posee el modelo más capaz hacia quién decide inteligentemente qué modelo usar y dónde ejecutarlo. Microsoft dispone de Windows, GitHub, Copilot y alianzas de hardware para unir esas capas. Es una ventaja de distribución, no una prueba automática de que su enrutamiento sea mejor que el de otros sistemas. Una evaluación independiente debería medir calidad, coste total, latencia, exposición de datos y recuperación ante fallos con tareas equivalentes.

Los desarrolladores interesados deberían preparar un conjunto pequeño de pruebas repetibles: revisión de código, cambios acotados y generación de tests, con resultados esperados. Cuando llegue la preview, conviene comparar ejecución local y remota, verificar el consumo de memoria y confirmar qué datos abandonan el equipo. También será necesario comprobar permisos de herramientas por separado, porque elegir un modelo local no sustituye el aislamiento de ejecución.

La lectura del Gazette

Análisis Gazette: la capa de orquestación puede importar tanto como el modelo individual; el beneficio solo será demostrable con costes y resultados comparables.

Análisis editorial

Consejos prácticos

  • No asumir que la preview está activa hasta que aparezca en el producto.
  • Medir consumo y calidad con tareas propias antes de sustituir modelos remotos.
  • Separar permisos de herramientas de la elección del modelo.

Limitaciones

  • No se confirmó distribución general inmediata de los pesos MAI Code locales.
  • Los claims de preservación de calidad y reducción de tamaño proceden de Microsoft.
  • El ahorro total frente a la nube depende de hardware y uso.

Resumen final

El cambio relevante es la integración de inferencia local, selección de modelos y herramientas de programación en Windows. Su impacto dependerá de pruebas reales de coste, calidad y seguridad cuando las previews lleguen a usuarios y desarrolladores.
